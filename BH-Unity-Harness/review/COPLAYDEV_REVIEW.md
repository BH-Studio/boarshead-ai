## Retained lessons and their use

| Lesson | Provider-neutral application |
|---|---|
| Explicit target identity | Select the full approved project and observe actual target/session identity; never choose the first available Editor. |
| Positive readiness | Missing, stale, busy or interrupted observations cannot establish readiness or a clean result. |
| Bounded inspection | Request stable object/asset identities and only relevant scalar properties; retain scope, coverage and truncation. Avoid whole-project dumps. |
| Actual schemas and APIs | Discover commands and public APIs for the installed version. Validate actual structured results and partial failures; exit zero is insufficient. |
| Submit once | Retain operation identity, deadline and raw terminal result. Lost responses and timeout do not justify blind replay or imply cancellation. |
| Nonatomic work | Prevalidate scoped action lists and inspect per-action results. Sequential batches can partly succeed; do not treat them as atomic. |
| Observable side effects | Identify refresh, focus, Play-state or timing changes before use. Obtain approval for stateful preparation and verify restoration. |
| Durable evidence | Persist raw results and current source identities before reload/interruption. Restored job metadata alone does not prove completed results survived. |
| Capability versus authorization | A visible catalog or supported tool does not authorize its use, package installation or a broader implementation task. |
| Efficient retrieval | Read the current contract and narrow reference first. Keep logs/captures in bounded artifacts and return concise supporting receipts. |

These lessons support the existing BH approval, evidence and optional observation contracts. They require no Coplay code or dependency. The generic BH runner and reducers remain disabled/unconfigured until a separately approved native mapping and actual host validation exist; fixture success is not Unity CLI compatibility proof.

## Execution decision

Use Unity CLI where its actual installed capabilities satisfy the approved task. A proposed alternative must demonstrate a specific CLI capability gap and provide strong comparative evidence about identity control, reliability, side effects, maintenance, dependencies and cost. The human must approve the exact exception before implementation or adoption. No such evidence has established a reason to abandon Unity CLI in this cleanup.

Do not revive the withdrawn Coplay discovery client, Editor handler, integration specification, action matrix or host pilot from historical records. The former CP-A/CP-B1/CP-B2/CP-B3 evidence is retained as historical provenance and is superseded by this disposition. No live project, package or host configuration is changed by this cleanup.
