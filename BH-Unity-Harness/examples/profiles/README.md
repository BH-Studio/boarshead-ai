# Synthetic project profiles

These examples are deliberately game agnostic. They test two different contract shapes: discrete-step state and continuous-time transient state. They define no product name, genre, gameplay loop, lore, fixed player count, engine patch, rendering pipeline, purchased asset or performance budget. Neither profile is an actual game design, a production overlay or approval to execute.

Both have `synthetic: true`, `status: SYNTHETIC`, no enabled optional capabilities and unresolved real-environment facts. Use them only with disposable synthetic fixtures. The runtime requires a real project to supply its own reconciled, approved inputs; changing a status label is not human approval.

Generate actual project overlays from the current project's approved artifacts using the shared contract. Never copy a historic game's policy into the standard. Earlier named-game examples were withdrawn by the user's game-agnostic scope clarification; their provenance remains in the review and Git history only.
