# Optional Project Auditor procedure

Not installed or implicitly discoverable in the standard template. Selection does not enable a provider or authorize package installation. Before optional adoption read [the observation setup](../unity-observation/README.md) and [provider protocol](../unity-observation/PROVIDER_PROTOCOL.md). Preserve this reference layout when making the procedure available; do not install a broken standalone SKILL file.

Require the actual project/session, installed Auditor rules, approved categories and scope, pinned comparable baseline, reviewed provider, current technical plan and exact acceptance expectations. Invoke the configured facts check through the normal verification route, never a guessed vendor command. One submit plus bounded local polling is sufficient; missing/partial/interrupted coverage is not a clean project.

Inspect the grouped delta, then only the raw CSV rows needed for the issue. Keep SonarQube and Auditor sources distinct. The raw report and provider identities remain in the receipt. Report new, resolved and existing findings with coverage limitations. Do not modify code/settings, install rules, change baselines, commit automatically or treat every recommendation as an instruction.

A scoped audit with no new findings can satisfy its automated criterion only after positive completed coverage. Gameplay and human acceptance remain separate. Repair requires returning to the existing approved execution/repair process. A timeout or lost job response requires ownership investigation before any resubmit.
