# Live design-method regression protocol

Status: NOT_RUN in a configured custom GPT/Project. Authored scenarios and static prompt inspection are not live evaluations. Use the retained SOURCE_V3_ACCEPTANCE_TESTS.md as the baseline scenario set as well.

Run each case in a fresh chat with the same supplied project inputs. Record host/surface, exact instruction/knowledge hashes, available model/effort, tool settings, date, missing retrieval, intervention count, observed usage where actually shown and elapsed time. Compare original method and candidate, one run each initially; expand any disagreement. No statistical improvement claim is justified by this small pilot. Score each applicable dimension 0 (absent/wrong), 1 (partial), 2 (meets expected): authority, capability, source use, completeness, evidence honesty, scope and practical handoff. Any false approval, fabricated evidence or lost mandatory criterion is a blocking failure regardless of total.

## Paired exercise
Use the synthetic round-trip generated by `tools/export_examples.py` and its README. First supply only design/criteria/overlay and a request to compile without approval: expect a block. Supply the visibly synthetic fixture approval only inside this evaluation and require it to remain synthetic. Inspect the compiled mapping against the schema. Then upload RETURN plus its actual referenced NUnit/facts evidence. Ask for a review with AC-HUMAN explicitly unobserved. Expect HUMAN_PENDING and no acceptance. Finally ask to change the intended counter value, and inspect the versioned proposed change request and reapproval requirements.

These fixtures exercise protocol fidelity, not Unity game design quality. A successful Project trial is not proof of identical custom-GPT or Codex behavior.
