# Unity procedures — retrieve only for the affected task

This conditional reference extends the existing five skills, not the always-loaded core. Approved project inputs own the UI framework, rendering, packages, asset paths, locales, mechanics and budgets. Reference recipes are evidence to evaluate, not authority to install tools or redesign the game.

## Inspect the narrowest useful state
For a scene/asset symptom, inspect the actual named object or bounded type/path/reference query before expanding into source search. Prefer stable object identities, asset paths and only the requested properties. Distinguish scene objects, project assets, disk text and indexed Search coverage. An incomplete index, unsupported provider or missing connection cannot establish absence. Avoid complete hierarchy/asset dumps. Opening a Search window is optional, not equivalent to returning inspected results.

Existing verified Editor/MCP routes are preferred over competing processes. Discover current names, argument shapes, target/session identity and package capabilities; do not copy assumed CLI flags from an old recipe. Batch remains an alternative only when its ownership requirements are satisfied. Do not install, upgrade, enable a global catalog, change security settings or kill an Editor to repair a connection.

## Observe asynchronous operations accurately
Trigger once; retain the job identity; wait through a local bounded operation with a deadline and terminal-state checks. Do not make repetitive model-driven status calls or relaunch after a lost response. Separate Editor readiness, operation completion and the actual acceptance observation. A domain reload may invalidate the session. Busy/unavailable/interrupted is not a clean scan; timeout is not server cancellation. Preserve unresolved ownership and inspect before another submit.

The optional BH observation modules require an adopted, tested provider and `reuse_policy: never`; they are not installed by default. When absent, report that capability unavailable instead of inventing a passing binding. File-bound unit checks may still reuse validated evidence as configured. Status/return validate historical artifacts; they do not observe current live state. Use a fresh operation for a current-state claim.

For Play-mode proof, observe actual frame or relevant state advancement, then each approved behavior and relevant errors. Select camera-versus-composited capture according to the criterion and save it to a bounded run file. A frame counter or screenshot alone does not prove functional UI, gameplay, visual quality or human acceptance. Record initial Play/ticking/background settings; only authorized preparation may change them, and restoration must be checked. Tuning/repair is execution work, not audit work.

## Persisted assets and UI completion
Before editing, identify the affected UI family and existing asset ownership; do not choose a framework from unrelated project files. Match the approved layout AND interaction requirements. A rendering-only prototype is sufficient only when the approved criterion explicitly says so. Do not discard event logic, controller behavior or data binding to match a recipe's narrow interpretation of “working UI”.

Prefer a complete bounded edit and targeted import/verification over repeated half-written assets or unrelated property changes. Preserve GUIDs, serialized references, prefab relationships and user edits. Inspect before creating; avoid destroy-and-rebuild repairs and duplicate components/listeners. Verify asset/sub-asset persistence from saved/reloaded data where required, not just non-null objects in memory. Check each required binding target, method, call state and observed behavior. Do not clear all listeners or overwrite an existing hierarchy just to make a sample idempotent.

Separate runtime UI from Editor preview. Detect the relevant uGUI/UI Toolkit/IMGUI pattern, existing input/event setup, size/layout ownership, focus/navigation, visibility and approved behavior. A successful import, compilation or wired-listener count alone is insufficient. State which checks need a real Editor, target build or human review.

## Package and specialist applicability
Inspect the exact Editor version, requested manifest, resolved lockfile and actual loaded capability as distinct facts. Discover supported public APIs in that version. Package resolution can be asynchronous; do not busy-wait on the Editor thread or exit before completion. Batch compatible approved changes rather than reinstalling packages one by one, but review the resulting dependency diff. Never copy an unrelated package's version, choose latest automatically, add missing packages without permission or treat a written lockfile as proof of loaded assemblies.

Load only the specialist reference needed for the observed problem. URP Render Graph rules do not apply to HDRP or every shader. Navigation checks must respect the project's existing backend and movement authority. Audio/TMP optimization requires comparable measurements and the approved quality envelope, not fixed bus-count/clip-duration/font rules. Collision symptoms warrant evidence-led diagnosis, not an unverified mandatory answer after an arbitrary tool budget. Missing information remains explicit.

For localization, compare against the approved key/locale roster and declared code-generated text sites; inspect both authored and composed text. Report absent/empty translations, unknown mappings and unconverted sites. Do not fill gaps with a fallback language to hide incomplete work. Separately test glyphs, fit, runtime switching and required preview behavior. Font/source copying requires appropriate rights; never treat installed system fonts as redistribution permission.

## Return only useful evidence
Use compact context/return views, acceptance IDs and current supporting receipts. Keep provider logs, captures and full audit reports in designated run artifacts. Summaries must disclose truncation and coverage. Audit findings do not authorize automatic cleanup; preserve the baseline and propose only scoped repairs. Human-only checks remain pending. Default tools never call a model API or launch an agent fleet.
