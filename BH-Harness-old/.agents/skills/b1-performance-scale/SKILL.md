# b1-performance-scale

Package: B1-CODEX-OPS | Version: 0.1.0
Authority: use only within the adopted repository instructions and the current authorized task.

## Entry and model

Read the approved performance claim, package workload and existing profiler/harness. Define
nominal, target, stress and safe guardrail axes relevant to this system: active/dormant AI,
concurrent attacks/projectiles, path requests, VFX/audio, players, duration, accumulated records,
or save size. Values must come from approved targets or clearly identified exploratory proposals.
Do not copy 5/100/2,000-system fixtures or 25/50-percent resource policies from the Galaxy source.

## Environment

Record actual CPU/GPU/RAM, OS, editor/player, Unity/package/build versions, scripting backend,
resolution/quality, synchronization/frame limits, power/thermal conditions when material and
network topology. The supplied RTX 2070 Mobile laptop/60-FPS target is a target context, not a
measurement or a universal per-subsystem allocation. Define missing settings before a binding gate.

## Measurement

Separate CPU main-thread, workers, GPU, allocations/GC, retained memory, I/O and network metrics
when relevant. Record warm-up, capture length, repetitions, sample count and distribution such as
median/tail frame time when meaningful. Distinguish initialization spikes from steady-state cost.
Do not add overlapping CPU/GPU timings as if they formed one serial frame duration.

Use comparable before/after builds/workloads for regression claims. Test relevant reload/retry,
scene unload and sustained-session accumulation. At stress, verify specified graceful degradation,
rejection, cleanup or recovery without inventing a new fallback that alters gameplay.

## Optimization discipline and output

Find the measured owner/bottleneck before changing architecture. Prefer a bounded fix and test it
against correctness/behavior contracts. New Jobs/ECS/Burst/pooling/streaming packages require scope.
Return workload/environment/units, thresholds, actual observations, variance, capture references,
limits and remaining validation. Editor observations do not certify target-player or Xbox performance.
No benchmark proves player experience or whole-system reuse.
