# b1-middleware-integration

Package: B1-CODEX-OPS | Version: 0.1.0
Authority: use only within the adopted repository instructions and the current authorized task.

## Entry and evidence

Read the approved task, technical asset register, repository map and Unity/middleware policy.
Identify exact installed vendor and integration versions from the checkout; use primary docs
for the matching release when needed. Owned, imported and production-accepted are different states.

## Ownership pass

Trace intent → navigation/planning → locomotion execution → collision/animation → gameplay
outcome → presentation. List the canonical state owner and allowed writers at every boundary.
Confirm UCC's bounded execution role and that project policy remains outside character-local
state. Verify Behavior Designer tasks and navigation adapters do not move the same actor through
competing direct transforms, physics or motors. Check supported interruption/ability hooks.

## Implementation pass

Prefer an existing supported seam over modifying vendor source. Add project-owned adapters
only at meaningful policy, compatibility, substitution or test boundaries; no universal wrapper
layer. Record component setup, version assumptions, define symbols, dependencies and exit path.
Do not install both Behavior Designer generations or add navigation/camera/input systems just to
make an example work. Rewired, A* and network candidates need applicable approval before adoption.

## Failure and lifecycle checks

Inspect invalid paths, lost targets, blocked movement, ability cancellation, death/downing,
scene reset, pooling, disabling/re-enabling and absent optional components as relevant. Confirm
one damage/resource owner and that VFX/audio do not repeat gameplay consequences. Test the
actual combination, not merely the existence of each package's documentation.

## Validation/output

Return the dependency/owner map, supported seam and source locator, installed versions,
setup diff, compatibility evidence, representative behavior checks and removal/upgrade risks.
Run approved PlayMode and player-build integration tests. If the only available API example is
for a different release or the bridge cannot be proven, mark that contract UNVALIDATED/BLOCKED;
do not invent signatures or patch vendor internals silently.
