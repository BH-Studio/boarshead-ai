# BH Arcade Assault Project — CURRENT_STATE

**Status:** `DRAFT / Phase 1 research`  
**Updated:** 2026-09-02  
**Active level:** `L3 Foundation`

## Current truth

Phase 0 migration and production-context verification are complete. The project has an approved engine baseline, production envelope, platform/session target, render-pipeline policy, and Opsive-first technical direction.

No active game concept or perspective has been approved.

## Approved or binding

- VECTOR RIFT is rejected as the active product.
- Unity 6.3 LTS.
- URP for the first game.
- Render-pipeline-independent core gameplay/framework contracts.
- Solo developer, evenings/weekends, approximately US$5,000 new-cash budget.
- PC first; Xbox probable but conditional; mobile deferred.
- Gamepad and mouse/keyboard support.
- Intended launch contract: solo plus exactly two-player online.
- Five-to-ten-minute arcade stages for early proof.
- Compact premium target built around roughly ten-to-twenty-minute operations.
- UCC is the default character execution substrate, subject to behavior validation.
- Behavior Designer Pro 3 and owned packs are available for AI validation.
- State Designer is owned and available but is not presently required.
- Synty and Marketplace assets are candidate resources, not automatic dependencies.
- Temporary overwhelming power is the invariant; vehicles are optional implementations.
- Persistent progression should be horizontal or tightly bounded.
- One or two consequential route decisions per operation.
- Proof order: interaction → inheritance → product → framework/second consumer → polished slice → production gate.

## Active candidates

- Iron Meridian as the first storyline.
- High-angle 3D twin-stick/isometric.
- Elevated arcade-chase third person.
- Adaptive third person that pulls back for dense combat.
- Rewired as the input backend.

- Behavior Designer Pro 3 + Tactical/Formations/Senses/Movement Packs.
- A* Pathfinding Project Pro.

## Deferred

- State Designer use until an actual recurring state-machine authoring need appears.
- Amplify Shader Editor as a runtime production dependency.
- Ultimate Inventory System until a substantial inventory/loadout product need exists.
- Public replay, leaderboards, procedural runs, many modes, split-screen, four-player co-op.
- Deep narrative design.
- Final progression strength, health/failure model, power-event form/count, authored/procedural ratio.
- Full GDD until perspective, storyline, launch session model, and production assumptions are sufficiently resolved.

## Principal risks

- UCC stock behavior substitutes for the intended source verb.
- Third person raises camera, aim, animation, off-screen fairness, and content burden enough to erase the production advantage.
- High-angle presentation reads as generic twin-stick rather than a distinctive modern assault game.
- Owned assets drive architecture through sunk-cost bias.
- Opsive/A*/AI packs create duplicate movement or hidden state ownership.
- Two-player online scope enters before the solo interaction is stable.
- Research expands into encyclopedia-building rather than answering product decisions.
- Chat history becomes the only source of truth.
