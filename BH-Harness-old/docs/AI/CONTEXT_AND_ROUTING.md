# Context, model choice, and optional delegation

Package: B1-CODEX-OPS | Version: 0.1.0 | Prepared: 2026-09-08
Status: CANDIDATE workflow; effective only after human adoption.

## Minimum useful context

Read root guidance, current task, baseline index/map and named package inputs. Search for exact
symbols/owners, then read complete relevant sections. Expand when contradictions or dependencies
require it. Do not preload all history, vendor manuals, narrative lore or skills for every task.
A summary navigates to evidence; it cannot replace a missing contract or approval.

Keep successful logs out of the conversation but retain their files. Include small failure excerpts
and evidence locators. Before context loss, record current revision/diff, verified and invalidated
evidence, blocker, next bounded action and required sources. Do not rerun unchanged discovery
ritually, or reuse old validation after relevant code changed. [B1-K10, B1-K12]

## Model and reasoning choices

No active model ID, reasoning effort, review model, login method, quota assumption or usage
threshold is installed by this pack. Select from the actual host/session capabilities. Use
stronger reasoning for ambiguous cross-system behavior, migration, authority, difficult failures
and consequential review. Mechanical extraction can use a lighter capability when outputs are
objectively checkable. Escalate based on errors and uncertainty, not model branding.

Track repeated correction cycles, missed contract impacts and inaccurate evidence summaries.
Never weaken an acceptance criterion to make a cheaper route appear adequate. Do not claim a
particular model is available, equivalent, cheaper or automatically selected without current evidence.

## One writer; bounded read-only help

The main Codex task normally owns all edits. Optional roles supplied in the distribution are
`b1_explorer`, `b1_contract_reviewer`, `b1_test_triage`, and `b1_evidence_reviewer`. They return
findings, not edits or approvals. They must not spawn other agents. Test triage reads supplied
logs; actual Unity execution belongs to the explicitly authorized runner/main task.

Each delegation names a single question, baseline/revision, exact input paths, read-only limits,
required output and stop condition. Return file/line evidence, classification, uncertainty and
smallest useful validation. Do not duplicate a settled full investigation. Shared sources are
not independent corroboration. No agent may extend its own authority.

Custom roles are optional examples, not installed or runtime-tested. If the host cannot load
them, perform the same bounded check sequentially. No subscription, Work mode, remote connector,
custom profile or API key is required. Current official local-Codex documentation describes
project-scoped custom roles, but host/version support must be checked before adoption. [EXT-CODEX-AGENTS]

## Writing concurrency

No parallel source, test, scene, prefab, package or shared-document editing in one checkout.
A future explicit worktree workflow must define isolated write sets, shared-contract ownership,
Unity project-copy strategy, import/build resources and an integration owner before parallel work.
It is intentionally not introduced by this pack.
