# Supported attempt and transfer check

**Draft research candidate — not released guidance.** Identity `GDR-CAND-20261010-F01-PAT-01` is temporary for `GDR-FULL-20261010/F01`. This file authorizes no implementation or adoption. Review and approval fields are intentionally null.

## Purpose

Help a player use a particular rule without indefinitely prescribing their next action. The technique pairs a representative supported attempt with a changed situation that tests the same intended relation, then adjusts only the instructional prompting. It is designed to distinguish following a prompt from using a rule, not to certify mastery or maximize time played. [C-01]

**Evidence status:** the complete recipe is an untested synthesis. Component sources motivate questions about task demands, guidance and later use; none validates the complete pattern. No player test, prototype or implementation was performed in F01. This is the only pattern extracted in the batch; no second pattern was manufactured.

## Context and prerequisites

Use only when there is a specific capability the player wants or reasonably needs for the intended activity, and when checking it will not remove the intended experience. A designer must be able to identify the real rule, a representative attempt, relevant feedback and a changed case that distinguishes plausible explanations. The player needs an accessible way to perceive and act on the relevant information. [C-01; C-02]

Practice must either be reversible or carry stakes that are both intelligible and appropriate to the intended activity. No rule in the practice context may silently teach a false version of the real interaction. The design needs a way to restore help, revisit the example and distinguish instructional prompts from accommodations and ordinary state information. These prerequisites are proposed safeguards, not empirically proven sufficient conditions. [C-02; C-07; C-09]

Do not infer readiness from demographic categories, the number of sessions played or one successful highlighted input. A player-selected route is a valid implementation of the concept; an adaptive classifier is not required. Engine, interface and data-storage choices require later design and approval. [C-02; C-07]

## Mechanism and evidence

| Causal link proposed by the pattern | Evidence bridge | Support and limit |
|---|---|---|
| Identify the particular knowledge/access gap → choose a fitting form of support | Expertise-reversal theory motivates treating relevant knowledge as a variable. [C-02; GDR-SRC-20261010-F01-11] | Indirect theoretical support. No validation of the proposed diagnostic or an automatic classifier. |
| Representative explanation/example → a usable initial model | A model can state the relationship the subsequent attempt must use. [C-03] | Author inference, not a direct experiment establishing this instructional format. An explanation may be ignored or misunderstood. |
| Attempt without supplying the next answer → retrieval or application of that relationship | Retrieval research supports a memory benefit in a vocabulary task. [C-04; GDR-SRC-20261010-F01-13] | Narrow laboratory support; action selection may instead reflect guessing, copying or another strategy. No game transfer guarantee. |
| Feedback tied to the relevant condition → correction of a misconception | Contrasting predicted and actual outcomes could discriminate explanations. [C-05] | Hypothesis. The vocabulary experiment did not test this feedback recipe. Too much explanation can disclose a desired secret. |
| Changed situation using the same relation → evidence beyond sequence copying | The check can rule out some alternative explanations if it is designed to do so. [C-06] | Measurement inference, not proof of durable or distant transfer. Novel demands can invalidate the comparison. |
| Reversibly taper answer-leading prompts → less unnecessary guidance while preserving participation | Tutorial heterogeneity and expertise theory justify testing this tradeoff. [C-07; GDR-SRC-20261010-F01-10; GDR-SRC-20261010-F01-11] | Whole link untested. Prompt removal may hurt; accommodations and ordinary information are not the variable to fade. |
| Later recap/optional attempt → usable re-entry | XAG guidance motivates revisitable information. [C-08; GDR-SRC-20261010-F01-14] | Practitioner rationale plus a new hypothesis; no direct game re-entry experiment inspected. |

The chain fails when a prerequisite link fails. It must not be presented as a universal “teach → test → reward” formula, and successful completion of one check does not validate the entire chain. [C-01; C-09]

## Recipe

1. **Select one capability and one misconception.** Write the rule in player-relevant terms and identify an incorrect but plausible alternative explanation. Also identify what the player does *not* need to learn yet. Exit if there is no meaningful capability distinction or if revealing the relation would spoil the core experience. [C-02; C-06]
2. **Confirm the route to participation.** Offer help or a relevant attempt in a way compatible with the player's access needs and preferences. Separate inability to perceive/execute from an incorrect model. Use direct choice rather than silent classification when diagnosis is unreliable. [C-02; C-07]
3. **Provide proportionate support.** Offer a concise explanation, a worked example or bounded investigation according to the learning question. Do not force an extra lesson solely because the pattern exists. Keep the practice rule consistent with the actual rule. [C-03; C-09]
4. **Invite an attempt with interpretable consequences.** Do not supply the next answer through mandatory highlighting when the purpose is to observe use of the rule. Permit recovery, a repeated example, more explanation or stopping. Capture a prediction only when it adds no unrelated language/access barrier. [C-04; C-05]
5. **Respond to the cause, not simply the score.** Identify the relevant condition and outcome, or provide a way to compare alternatives without revealing protected information. A failure caused by access, latency, hidden state or a teammate is not automatically a learning failure. Exit this diagnostic route when the cause cannot be distinguished. [C-05; C-09]
6. **Offer a changed, representative case.** Change a feature that makes the original sequence insufficient while preserving the rule and access conditions. Check whether the player uses the relation, not whether they repeat the demonstration. Treat a result as limited evidence; offer support again when uncertainty remains. [C-06]
7. **Adjust instructional prompting reversibly.** Reduce answer-leading prompts only when the check and player preference justify that change. Retain an example/reference, a clear help route, accommodations and ordinary game-state feedback. A player who wants prompts may retain them; the technique does not require stripping support as a reward. [C-07]
8. **Plan later re-entry where it matters.** After an absence or a meaningful rule/state change, offer the relevant intention/state recap and optional practice. Do not repeat every lesson or presume that elapsed time proves forgetting. [C-08]

**Exit conditions:** stop applying this pattern when the rule is unstable; the practice is unrepresentative; the necessary information is inaccessible; the transfer check introduces unrelated difficulty; the user declines redundant support; revealing the relation destroys intended discovery; or fading would remove an accommodation. Choose direct instruction, player-requested help, ordinary play or another design—not a forced repetition of a failing lesson. [C-09]

### Adjustable variables

Adjust the scope of the target capability, amount and form of initial explanation, reversibility of practice, timing and detail of feedback, dimension varied in the check, player control over support and the relevance of a later recap. Every adjustment changes either the learning demand, interpretability or burden and must be tied to the decision being tested. [C-01; C-03; C-05; C-06; C-08]

No universal attempt count, time limit, mastery percentage, hint delay, absence interval or sample size is specified. The game team must set any local values and justify them before evaluating a candidate. A source's experimental interval is not a pattern parameter by default. [C-04; C-10]

## Worked examples

### Illustrative complete example: reserved versus spendable resources

**Intended capability:** recognize that a reservation reduces immediately spendable resources even though the total owned amount has not changed. **Plausible misconception:** everything owned can be spent again. The invented local example starts with 6 units, of which 4 are reserved; only 2 remain spendable. These numbers illustrate a distinction and are not balance recommendations. [C-03; C-06]

First, make the reservation rule available and explain what is committed. Invite a reversible decision to spend 3 units or change the reservation. Feedback should distinguish the owned total from the spendable amount and explain why the attempted spend did or did not satisfy the rule. Presentation determines the accessible form; this pattern does not prescribe colors, layout or sound. [C-05; C-07]

For the changed case, use 10 owned units with 7 reserved and a proposed spend of 4. Simply choosing the visually larger total is now an inadequate strategy. A relevant response can be to release enough reserved resources, choose a different purchase or decline the spend. The check is about the relation, not a compulsory preferred purchase. A player who makes an unexpected choice for another valid goal has not necessarily misunderstood. [C-06]

If the relation is used intelligibly, offer to continue without answer-leading prompts while retaining the resource information and help. If confusion persists, test whether “reserved” is understood and whether both quantities are accessible before repeating the lesson. If an assistive route is required, retain it irrespective of check performance. No player results exist for this example. [C-05; C-07; C-09]

### Illustrative adaptation: a returning player

A returning player remembers how reservations work but not which commitments remain. Offer the existing commitments and a safe next action, not the original arithmetic lesson automatically. A player who requests a refresher can use the same rule in an optional reversible situation. If the rule changed while they were absent, explicitly identify that change rather than presenting the old tutorial as authoritative. [C-08]

This may reduce irrelevant repetition, but it may also be unnecessary when the ordinary state presentation is sufficient. Compare the recap with no automatic intervention and accessible on-demand history before adding an elaborate return sequence. [C-08; C-10]

## Tradeoffs and alternatives

The pattern creates additional content, diagnostic assumptions and maintenance. A direct explanation can be cheaper and clearer. A player-selected “practice this” route can avoid unreliable adaptation. Ordinary play can supply representative practice without a separate tutorial. A reference page can be enough for someone who knows what to look up. A designed discovery sequence may legitimately avoid explicit explanation of its hidden rule. [C-01; C-09]

No single alternative wins by default. The strongest reason to use the pattern is a consequential gap between following instruction and using a particular rule; the strongest reason not to use it is that checking and tapering add burden without addressing such a gap. Where predictable rule use is not an intended experience, the pattern may optimize the wrong outcome. [C-01; C-09]

## Failure cases

| Observable warning sign in a future test | Competing explanation to inspect | Conditional correction |
|---|---|---|
| Guided success followed by failure on the changed case | Sequence copying, an inaccessible distinction or extra demands in the check | Redesign the discriminating case; do not merely repeat the prompt. [C-06] |
| Player repeatedly declines or abandons practice | Already knows the rule, wants another activity, or finds the support inaccessible | Offer ordinary play or a different help route; do not infer low motivation automatically. [C-02; C-09] |
| Support removal produces avoidable errors | Check was too easy, luck explained success, or removed information was necessary access | Restore support and separate instructional prompts from participation requirements. [C-07] |
| Explanations improve completion but reduce the desired experience | A secret or interpretive choice was the intended activity | Do not apply the pattern to that secret; restrict teaching to prerequisites. [C-09] |
| A recap contradicts current shared state | Another participant or a rule update changed the situation | Correct the state account; suspend the lesson until it represents the current rule. [C-08] |

These are predicted failure cases, not observations made in F01.

## Counterexamples and do not use conditions

An experienced player encountering a familiar relation may gain nothing from a mandatory check. A player seeking uninterrupted exploration may prefer accessible reference without an intervention. A mystery whose central activity is discovering the relation would be damaged by an explicit model. A player whose assistance compensates for an enduring access need must not lose that assistance because they passed a learning check. [C-07; C-09]

The tutorial study's heterogeneous engagement outcomes oppose a blanket expectation that more structured instruction helps every game. The retrieval study supports a narrow memory result, not a reason to turn every interaction into a test. These contrary limits are reasons to compare simpler alternatives, not excuses to deny access. [C-04; C-09; GDR-SRC-20261010-F01-10; GDR-SRC-20261010-F01-13]

## Playtest

**Proposed; not performed.** Compare the full pattern with a minimal relevant explanation plus ordinary play. Where justified, include player-selected reference/practice as an alternative. Keep accommodations and ordinary state information available in every condition; do not test the pattern by denying access. [C-10]

Use a target rule, a matched initial case and a changed case that distinguishes a known misconception. Record immediate use, changed-case choices, relevant explanation or nonverbal prediction, recovery, unwanted interruption and help preference. A later comparable task can assess continued use, but its timing must match the research question. Record practice exposure, task familiarity, language and input/access context so extra time is not silently credited to the pattern. [C-06; C-10]

The intended participant groups are relevant novices, experienced players and returning players, with the access needs actually in scope. Select sample and analysis from a future test design; F01 supplies no invented power guarantee. Review the comparison for fairness, consent and discovery spoilers before recruiting. [C-10]

**Falsifiers:** reject the proposed advantage when gains are confined to guided completion; changed-task use is no better than the simpler alternative; reduced prompting increases misunderstanding; access is lost; or the added check produces an unacceptable loss of the intended experience. A result favoring one group should narrow applicability rather than establish a universal rule. The decision owner must choose local benefit and harm criteria in advance. [C-10]
